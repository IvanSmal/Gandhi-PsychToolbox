# Timing in saved trials

How every time in a saved trial is measured and calculated, and how to
compare them.

## In short

- **One timeline.** Every saved time whose name ends in `_ms` is
  **milliseconds since the trial start**, measured on the **NIP (Trellis)
  clock**. The trial start is the moment `setstate('start_autogenerated')`
  ran. Any two `_ms` values can be subtracted, whatever they belong to: a
  target, a state, an eye sample, a cursor sample.
- **Trellis / neural data.** `trial.start_tick` is the trial start as a NIP
  tick (30 000 ticks per second). For any time,
  `tick = trial.start_tick + 30 * ms`. Columns ending in `_tick` are already
  NIP ticks.
- **Each object carries its own timing.** `trial.targets.<name>`,
  `trial.tags.<name>` and `trial.state.<name>` each hold when they were asked
  for, when they reached the screen and when their light appeared. The same
  numbers are also in two flat tables, `data.stimulus_events` and
  `data.stimulus_frames`, for looking at everything at once. The copies are
  made from the same values, so they always agree.
- **Negative times** are before the trial started, for example the eye
  samples recorded during the inter-trial interval.

| To find | Look in |
|---|---|
| When a state began, reached the screen, lit the photodiode | `trial.state.<name>` |
| When a target appeared / disappeared | `trial.targets.<name>.events` |
| Where a target was on every frame it was shown, and when | `trial.targets.<name>.frames` |
| Every position the task calculated for a moving target | `trial.targets.<name>.computed` |
| The same for an item drawn with `mh.Screen(..., 'Tag', name)` | `trial.tags.<name>` |
| Time of each eye / photodiode sample | `data.time_ms` |
| Time of each cursor sample | `data.cursor(k).time_ms` |
| Everything that changed on screen, in one table | `data.stimulus_events` |
| Every item on every frame, in one place | `data.stimulus_frames` |
| How the times were made (clock fit, photodiode delay, raw values) | `data.clock_sync` |
| How to check the photon times on a rig | *Checking photon times on a rig*, below |

### Examples

```matlab
t  = e.trial(4);
T  = t.targets.T1_Moving_CW_12;
S  = t.state.T1_reach_state_moving;
d  = t.data;

T.events.photon_ms(1) - T.events.requested_ms(1)     % asked for -> light on screen
T.events.photon_ms(1) - S.photon_ms(1)               % target's light vs its state's photodiode change
interp1(d.time_ms, d.eyepos', T.events.photon_ms(1)) % eye position when the target appeared
plot(T.frames.displayed_ms, T.frames.x_deg)          % where the target was shown, over time
t.start_tick + 30 * T.events.photon_ms(1)            % the same moment as a Trellis tick
```

## Field by field

### Trial

| Field | What | How |
|---|---|---|
| `start_tick` | the trial start as a NIP tick, t = 0 of every `_ms` | `setstate('start_autogenerated')`'s Psychtoolbox time put on the NIP clock (see *Clocks*). Not rounded, so the start is exactly 0 ms. |
| `start_clock` | date and time of the trial start (wall clock) | `datetime('now')` in `starttrial`. For comparing trials and for people; never used for timing within a trial. |
| `stop_ms` | the end of the trial | when MHost2 finished the trial loop and its post-trial checks. The inter-trial interval is counted from this moment. It can fall a few ms after the last eye sample. |

### `trial.state.<name>`

One row per **entry** into the state (`setstate` called with that name).

| Field | What | How |
|---|---|---|
| `count` | number of entries | |
| `requested_ms` | when `setstate` ran | Psychtoolbox time at the call. |
| `displayed_ms` | when the first frame of the new state reached the screen | the flip that changed the photodiode square's colour (it changes on every state change; see *Displayed*). |
| `photon_ms` | when the photodiode square's light changed | measured in the photodiode trace (see *Photon*). |
| `delay_ms` | `displayed_ms - requested_ms` | |
| `code` | the marker this state sends to Trellis | see *Trellis markers*. |

`displayed_ms`, `photon_ms` and `delay_ms` are NaN for an entry that never
changed the screen:
- a **state shorter than a frame** (left again before the display drew it);
- a **repeat**: `setstate` called again with the state already active. That
  adds an entry, but nothing changed on screen.

### `trial.targets.<name>`

The target's settings as the trial used them (position, size, colour, speed,
...), plus three tables.

**`events`**: one row per appearance (`event` `on`) and disappearance (`off`).

| Column | What |
|---|---|
| `event`, `state` | `on` / `off`; the state when it was asked for |
| `requested_ms` | when MHost2 published the first frame that included (or left out) the target |
| `displayed_ms`, `photon_ms`, `delay_ms` | as for states; `photon_ms` is derived from the photodiode (see *Photon*) |
| `x_deg`, `y_deg` | where it was shown (centre of its box, degrees; see *Positions*) |
| `frame_id`, `missed` | the frame that showed it; whether that flip missed its deadline |

**`frames`**: one row per frame it was on screen. Columns: `frame_id`,
`requested_ms` (when MHost2 published that frame), `displayed_ms`,
`photon_ms`, `x_deg`, `y_deg`, `rect_px`, `missed`, `state`.

**`computed`**: one row per position the task calculated (each `getpos`
call), whether or not it was ever drawn. Columns: `time_ms` (when `getpos`
ran), `x_deg`, `y_deg`. A target that does not move has one row with
`time_ms` NaN.

`frames` is what the subject saw. `computed` is what the task calculated;
the eye and cursor checks use it. A frame shows the last position calculated
before it was published.

A target that was fetched but never drawn has empty `events` and `frames`.
Targets are recognised automatically: a drawing command at the rectangle
`getpos` returned is that target.

### `trial.tags.<name>`

Items drawn with `mh.Screen(..., 'Tag', name)`, for example
`mh.Screen('FillRect', 'windowPtr', [1 1 1], cueRect, 'Tag', 'cue')`. Same
`events` and `frames` as a target, plus `name` (the tag as written; the field
name is made a valid MATLAB name). Only what is drawn on the display counts,
not `'monitoronly'`. Same-named commands in one frame are one item.

### Eye, photodiode and cursors

| Field | How |
|---|---|
| `data.time_ms` | one value per eye / photodiode sample (1 kHz). Sample *k* was taken at NIP tick `trace_start_tick + 30*(k-1)`, so `time_ms(k) = (trace_start_tick + 30*(k-1) - start_tick) / 30`. The trace starts with the first NIP read, before the inter-trial interval, so the first samples are negative. `data.clock_sync.trial_start_sample` is the sample nearest 0. |
| `data.cursor(k).time_ms` | one value per cursor sample. Analog cursors: the NIP tick of the sample read, converted directly. udp cursors: the Psychtoolbox time when MHost2 read the shared slot, put on the NIP clock. |

### `data.stimulus_events`

One row per item appearing or disappearing, and per state change, in the
order they were asked for. Each target, tag and state above is a slice of
this table.

| Column | What |
|---|---|
| `tag`, `kind` | the item (`target`, `tag`, or `photodiode` for a state change) |
| `event` | `on`, `off`, or `state` |
| `state` | the state it was asked for in (for state rows: the new state) |
| `entry` | state rows: which entry into the state (row *k* of `trial.state.<name>`) |
| `requested_ms` | items: when the first frame with the change was published. State rows: when `setstate` ran (the same value as in `trial.state`). |
| `displayed_ms`, `displayed_tick` | when the change reached the screen |
| `photon_ms`, `photon_tick` | when its light appeared |
| `delay_ms` | `displayed_ms - requested_ms` |
| `flip`, `frame_id` | the flip (count within the trial) and the frame it showed |
| `x_deg`, `y_deg`, `rect_px` | where (see *Positions*) |
| `missed` | Psychtoolbox reported that flip as late |

A change that never reached the screen (gone again before the next flip)
keeps `displayed_ms` NaN. A change seen on screen with no request on record
gets a row with `requested_ms` NaN.

### `data.stimulus_frames`

One entry per item, with one row per flip it was on screen: `name`, `kind`,
`flip`, `frame_id`, `requested_ms`, `displayed_ms`, `photon_ms`,
`displayed_tick`, `photon_tick`, `x_deg`, `y_deg`, `rect_px`, `missed`,
`state`. Here `requested_ms` is always when that frame was published. The
`photodiode` entry has one row per colour change (one per state change) and a
`color` column.

### `data.clock_sync`

Everything needed to check or redo the times. These are the only raw clock
values in a saved trial.

| Field | What |
|---|---|
| `nip_pairs` | `[GetSecs tick]`, one row per NIP read this trial |
| `fit` | `ticks_per_s`, `tick_at_0` (`tick = ticks_per_s*GetSecs + tick_at_0`), `pairs`, `read_delay_ms` |
| `trace_start_tick` | NIP tick of eye/photodiode sample 1 |
| `trial_start_tick` | the same as `trial.start_tick` |
| `trial_start_sample` | the eye/photodiode sample nearest t = 0 |
| `start_secs`, `stop_secs` | Psychtoolbox times of the trial start and stop |
| `first_frame_id` | the first frame this trial published |
| `photodiode` | `used`, `changes`, `found`, `lag_ms`, `lag_spread_ms`, `note` (see *Photon*) |
| `frame_ms` | the display's frame duration this trial |

## How it is calculated

### Clocks

Three clocks are involved. Only one appears in the saved `_ms` times.

1. **NIP (Trellis), 30 kHz ticks.** The neural data, the eye and photodiode
   samples, and the analog cursors are sampled on it. This is the reference.
2. **Psychtoolbox `GetSecs`.** While a trial runs, MHost2 stamps everything
   it does with it (`setstate`, `getpos`, each published frame), and
   GraphicsHandler gets each flip's time on it from Psychtoolbox. Both
   processes are on the same machine, so their values are directly
   comparable.
3. **Wall clock.** Only `trial.start_clock`, `e.Date` and file and folder
   names.

**Putting `GetSecs` on the NIP clock** (`nipTick`, `nipClock`). Every time
MHost2 reads the NIP in the trial loop (about once per ms), it logs a pair:
the `GetSecs` time when the read returned, and the tick of the newest sample
the read got. That sample is already a little old, by a varying amount, so
`GetSecs - tick/30000` is the clock offset plus that age. In each second the
smallest value is a read that found a fresh sample. A straight line through
those per-second minima gives the offset and its drift (the drift is fitted
only when the trial lasts 5 s or more). The result is saved as
`clock_sync.fit`; `read_delay_ms` is the typical age of the newest sample
when it was read. If a trial has no NIP reads, the `GetSecs` times are kept
relative to the trial start instead (not on the NIP clock), and `fit.note`
says so.

### The trial start

`starttrial` records a first estimate: the NIP tick then, and the wall-clock
time. When the trial is saved, `trialRecord` replaces the tick with
`start_autogenerated`'s `GetSecs` put on the NIP clock with the fit. That is
`trial.start_tick`.

### Requested

- **States:** `GetSecs` when `setstate` ran.
- **Items** (targets, tags): `GetSecs` when MHost2 published the first frame
  that included the change (`publishFrame`). Each published frame lists the
  items it draws. MHost2 compares that list with the previous frame's and logs
  every appearance, disappearance and state change, with the frame's number
  and time.
- **Frames:** `GetSecs` when that frame was published. The renderer logs it
  with each flip.
- **Computed positions:** `GetSecs` when `getpos` ran.

### Displayed

GraphicsHandler draws the newest frame MHost2 has published, flips, and logs
the flip: Psychtoolbox's `StimulusOnsetTime`, the frame number, what that
frame drew and where, and whether the photodiode square changed colour. For
each item, every flip where it is on screen but was not on the previous flip
is an appearance; the reverse is a disappearance. Each one is matched to the
latest request for the same change made in a frame at or before the one shown.
`displayed` is that flip's `StimulusOnsetTime` put on the NIP clock.

The square in the display's corner changes colour on every state change, so
the flip that changes it is the state's `displayed` time. At the end of a
trial, the flip that clears the display is where everything still shown
disappears.

### Photon

`displayed` is when the display started drawing the frame. `photon` is when
light appeared at the item's place on the screen. It is measured with the
photodiode on the corner square:

1. **Find the square's colour changes in the photodiode trace.** The
   threshold is halfway between the trace's 2nd and 98th percentiles. Each
   crossing is placed between samples by linear interpolation.
2. **Match them to the flips that changed the square.** First pass: the first
   crossing from 2 ms before to 80 ms after each such flip. Their median is
   the typical delay. Second pass: for each flip, the crossing nearest to
   flip + typical delay, within 3 ms (or 3 times the first pass's median
   absolute deviation, if larger).
3. **Accept the result** only if at least half the changes were found and
   the delays agree to within 3 ms (median absolute deviation). Otherwise
   every `photon` value is NaN and `clock_sync.photodiode.note` says why. This
   is what happens in demo mode, and when the photodiode is not connected.
   `lag_ms` is the median delay from flip to light at the square;
   `lag_spread_ms` is how much it varies.

A state's `photon` is its measured crossing. An item's `photon` comes from the
square's typical delay plus the scan-out difference. The display draws from
top to bottom over one frame, so an item higher up lights before the square
at the bottom:

```
photon_tick = displayed_tick + lag - scan(square's height) + scan(item's height)
scan(y)     = y / display height * frame duration * 30000
```

The item's height is the middle of the part of its box that is on the
display. An item entirely off the display gets NaN. The frame duration is the
median interval between this trial's flips (`clock_sync.frame_ms`).

How to check photon times on a rig: *Checking photon times on a rig*, below.

### Positions

`x_deg`, `y_deg` are degrees of visual angle, 0 at the display's true centre
(rig config), +x right, +y up. For `events` and `frames` they are the centre of
the item's box on screen. `rect_px` is that box, `[left top right bottom]` in
display pixels, covering every drawing command of the item in that frame. For
`computed` they are the position `getpos` calculated, converted from the
target's units (cartesian degrees as is; polar to cartesian; mm through
pixels).

### Trellis markers

Every `setstate` sends the state's code (`trial.state.<name>.code`; the
session's table is in `data.stateCodes`) as one parallel-port marker on
digital output 5. Trellis records it with a NIP timestamp, so state onsets
are also in the `.nev` file, already on the NIP clock. In addition, digital
output 1 goes high when MHost2 starts preparing a trial (before the
inter-trial wait) and low when the trial loop ends, and digital output 4 goes
high at the trial start and low about 50 ms later. These markers are when MHost2 sent them, not when the
display changed: for that, use `displayed_ms` / `photon_ms`.

## Checking photon times on a rig

`photon_ms` depends on the photodiode, so it can only be checked on a rig
with the photodiode connected (in demo mode, and in the VM, it is always
NaN). Do the checks in this order: each one depends less on MHost2 than the
one before.

### 1. In the saved session

**Did the photodiode calibrate in every trial?**

```matlab
P = arrayfun(@(t) t.data.clock_sync.photodiode, e.trial);
fprintf('photodiode used in %d of %d trials\n', nnz([P.used]), numel(P));
unique({P(~[P.used]).note})                            % why not, for the others
fprintf('lag %.2f-%.2f ms (median %.2f), largest spread %.2f ms\n', min([P.lag_ms]), ...
    max([P.lag_ms]), median([P.lag_ms], 'omitnan'), max([P.lag_spread_ms]));
```

Expect:
- used in nearly every trial. A trial that ended after a fraction of a
  second may have too few state changes ("too few photodiode edges near the
  colour changes").
- `lag_ms` the same from trial to trial, to within about a millisecond. It is
  the display's own delay (its input lag, plus the time it takes to draw down
  to the square), so it differs between displays. The 120 Hz display recorded
  on 2026-10-22 gave 8.3-9.0 ms, median 8.5 ms.
- `lag_spread_ms` well under 1 ms (0.1 ms on that display).

A lag that jumps between trials, or a spread near the 3 ms limit, means the
wrong crossings are being picked. Check the channel, that the sensor sits
over the square, and that the trace is a clean two-level signal (next check).

**Do the photon times sit on the photodiode's steps?** Plot one trial:

```matlab
t = e.trial(find([P.used], 1)); d = t.data;           % a trial where it was used
st = struct2cell(t.state); st = [st{:}];             % all its states
on = vertcat(st.displayed_ms); ph = vertcat(st.photon_ms);
figure; plot(d.time_ms, d.photodiode); hold on
xline(on(isfinite(on)), 'k:');                       % the flips
xline(ph(isfinite(ph)), 'r');                        % the light
xlabel('ms since the trial start')
```

The square changes between black and white at every state change, so the
trace steps up or down at each one. Each red line should be on a step,
halfway up it when you zoom in, and each dotted line should be the same
`lag_ms` before its red line.

**Are the items' photon times in range?** An item's photon time is not
measured: it is the square's delay, shifted by where the item is on the
display. An item higher up lights earlier than the square at the bottom, by
up to one frame:

```matlab
C = d.clock_sync;
F = d.stimulus_frames.T1_Moving_CW_12;                % any target or tag
L = F.photon_ms - F.displayed_ms;
fprintf('%.2f-%.2f ms, expected within %.2f-%.2f ms\n', min(L), max(L), ...
    C.photodiode.lag_ms - C.frame_ms, C.photodiode.lag_ms);
```

### 2. Against the Trellis recording

Trellis records the same signals on its own, so this checks what the session
cannot check by itself: how MHost2 placed its photodiode samples on the NIP
clock, how it found the steps, and its `GetSecs` -> NIP clock fit.

Before recording:
- In Trellis, save the photodiode's analog input, preferably at 30 kHz
  (1 kHz works). MHost2 reads it as the fourth analog channel,
  `app.chidx(4)`. Also save the digital (parallel port) input that carries
  the state markers.
- Tick RECORD NEURAL DATA. MHost2 then makes one Trellis recording per trial,
  numbered `trial.trellis_trial_number`. Each starts before the inter-trial
  wait and stops after the trial.

Run 20 or more trials of a task with several states and a moving target.
For each trial, open its Trellis files with Ripple's MATLAB tools for Trellis
files (Neuroshare: `ns_OpenFile`, `ns_GetAnalogData`, `ns_GetEventData`).
Get, in the file's own time:
- **steps**: the photodiode crossings, found the way MHost2 finds them
  (threshold halfway between the 2nd and 98th percentiles, each crossing
  interpolated between samples);
- **markers**: the digital events. Each one's value is a state's code,
  `t.state.<name>.code` (the session's table is `data.stateCodes`). Entry *k*
  of a state is that code's *k*-th marker; its step is the first step after
  the marker. When the display is cleared at the end of the trial, a white
  square disappearing makes one more step, after the last state's: ignore it.

Compare only differences within a trial, so the file's time origin does not
matter:

| From Trellis | From the saved trial | Checks | Expect |
|---|---|---|---|
| step - first step | `photon_ms` - the first state's `photon_ms` | the photodiode samples' times; the step finding | equal to within about 0.5 ms |
| marker - `start_autogenerated`'s marker | `requested_ms` | the clock fit | equal to within about 1 ms, with no drift over the trial |
| step - the same state's marker | `photon_ms - requested_ms` | everything together | differ by the same amount for every state (the marker's own delay, a fraction of a ms) |

If the files turn out to store the NIP's own ticks, rather than time since
the file started, `photon_tick` and the markers can also be compared with the
saved ticks directly.

### 3. The correction for an item's height

Items' photon times assume the display draws from top to bottom, at a steady
speed, once per frame. To check that on a display, measure the square's
delay at two heights:

1. Record a few trials with the square at the bottom, where it normally is.
   GraphicsHandler draws it at `gr.diode_pos = [0, H-20, 20, H]` (the
   bottom-left 20 px; `H` is the display's height in pixels).
2. Change that line in `GraphicsHandler.m` to the top-left, `[0, 0, 20, 20]`,
   move the sensor there, restart, and record a few more. Put the line back
   afterwards; do not commit it.
3. At the top, `lag_ms` should be shorter by (H - 20) / H x `frame_ms`. For
   a 1080-pixel display at 120 Hz, that is about 8.2 ms.

If it does not match, item photon times can be off by up to a frame. Some
displays update in a different order, or light the whole panel at once (a
strobed backlight). States are measured directly and are not affected.

## What is not on the timeline

- `e.Date`, `trial.start_clock`, and the date/time folder and log names:
  wall clock, for people.
- `e.LastParameters`: the internal object as it was when Stop was pressed.
  It holds live values (`GetSecs`) and the trial that was in progress then,
  which is not `e.trial(end)`. Use `e.trial` for data.
- The reward handler and the udp cursor slot keep their own times
  internally; none of it is saved.

## Data saved before this layout

Sessions recorded before this change use other names and clocks. A trial has
the old layout if `trial.state.<name>` has a `time` field (and `start_tick`
is empty or missing).

| Old | Clock | Now |
|---|---|---|
| `trial.tstarttime` | `getsecs`: seconds since local midnight | `start_tick`, `start_clock`; the start is 0 ms |
| `trial.tstoptime` | `getsecs` s | `stop_ms` |
| `trial.state.<name>.time` | `getsecs` s | `requested_ms` |
| `trial.targets.<name>.timestamp`, `moving_position` | `getsecs` s | `computed.time_ms`, `x_deg`, `y_deg` |
| `data.timestamps` | `getsecs` ms | `data.time_ms` (old: `timestamps - floor(tstarttime*1000)`) |
| `data.cursor(k).timestamps` | `getsecs` ms | `data.cursor(k).time_ms` |
| `stimulus_events.requested`, `displayed`, `delay` | `GetSecs` s | `requested_ms`, `displayed_ms`, `delay_ms` |
| `stimulus_events.onset_tick`, `stimulus_frames.onset_tick` | NIP | `displayed_tick` |
| `stimulus_frames.onset` | `GetSecs` s | `displayed_ms` |

`getsecs` (lower case) read the wall clock. It jumps when the system clock is
corrected and restarts at midnight, which is why nothing uses it any more.
